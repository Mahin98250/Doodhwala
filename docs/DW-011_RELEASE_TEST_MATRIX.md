## Status and evidence rules

- **PASS** only for the exact scope and commit actually tested; narrow UI mocks/static contracts are not authenticated backend E2E.
- **FAIL** means a reproducible assertion failed and must link a finding/PR.
- **BLOCKED** means a required safe environment, configured provider, device or approval is unavailable.
- **NOT RUN** means no evidence was executed/observed for this row yet.
- Evidence must capture commit SHA, environment, browser/device/viewport, exact command or steps, expected vs actual, status, artifact/log, and follow-up.
- Never put secrets, customer PII, live order IDs, payment credentials or precise real GPS routes into artifacts.
- **Safe database target currently available:** disposable PostgreSQL used by CI migration-validation fixtures only, with synthetic fixtures. It is safe for the SQL suites that explicitly create disposable databases. It is not an application staging environment and does not prove Supabase Auth, RLS, Realtime, Edge Functions or end-to-end behavior.
- **No safe Supabase staging project is currently provisioned or verified.** The last documented read-only production audit is for project `hmiboyfcvtfawrwujslg` in `ap-south-1`; this is production and is **not a test target**. Do not run synthetic writes or load tests against it. The two-free-project limit blocked staging creation and a development branch had a quoted non-zero cost; no paid project/branch is approved.
- **Schema drift is known:** repository migration state does not match the production migration history/catalog snapshot. Never infer schema availability from a migration file or a green SQL fixture run. Reconcile a dedicated staging project's actual migration history and catalog before database E2E.
